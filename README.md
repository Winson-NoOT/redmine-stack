# redmine-stack

Portable Docker Compose stack for [Redmine](https://www.redmine.org/) 6.1 with two plugins:

- [`redmine_mcp`](https://github.com/Winson-NoOT/redmine_mcp) — Model Context Protocol server, OAuth 2.1 + PKCE
- [`redmine_issue_update_statistics`](https://github.com/Winson-NoOT/redmine_issue_update_statistics) — per-field issue update stats

Both are forks owned by `Winson-NoOT`. Redmine talks to a Postgres 16 sidecar.

## Quick start

Requires `docker`, `docker compose`, `git`, `openssl`, and `bash`.

```sh
git clone https://github.com/Winson-NoOT/redmine-stack.git
cd redmine-stack
./bootstrap.sh
```

`bootstrap.sh` is idempotent: it generates `.env` if missing, clones the two plugin forks into `plugins/`, brings the stack up, installs plugin gems, runs `rake redmine:plugins:migrate`, and restarts Redmine.

Redmine ends up on `http://localhost:3000` (or `REDMINE_PORT` from `.env`). First login: `admin` / `admin`.

## Layout

```
redmine-stack/
├── docker-compose.yml
├── .env                 # generated by bootstrap.sh (gitignored)
├── .env.example
├── bootstrap.sh
├── plugins/             # bind-mounted to /usr/src/redmine/plugins
├── themes/              # bind-mounted to /usr/src/redmine/themes
└── files/               # bind-mounted to /usr/src/redmine/files
```

`pgdata` lives in a named Docker volume, not on the bind mount, so Postgres I/O isn't slowed by the host filesystem.

## Updating plugins

```sh
cd plugins/redmine_mcp        && git pull && cd ../..
cd plugins/redmine_issue_update_statistics && git pull && cd ../..
docker compose exec -u root redmine bundle install
docker compose exec -u root -e RAILS_ENV=production redmine bundle exec rake redmine:plugins:migrate
docker compose restart redmine
```

## Teardown

```sh
docker compose down        # stop, keep data
docker compose down -v     # stop + wipe pgdata and uploads
```

## Notes for Claude Code cloud sandboxes

This stack is designed to be cloned and run inside an ephemeral Linux sandbox (e.g. `claude.ai/code`). Postgres data lives in a Docker named volume — anything in `pgdata` disappears when the sandbox shuts down. If you want a persistent instance, host this on a real VM.
